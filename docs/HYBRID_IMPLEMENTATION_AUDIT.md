# Hybrid implementation audit

2026-10-24. Baseline main: 09b9cba. Implementation branch: feature/hybrid-creature-slice. Unity 6000.6.7f1. BWVR only; Shade is outside this change.

## Reconnaissance and reusable systems

Read README, GAMEPLAY_DIRECTION, CREATURE_BEHAVIOR and VR_SLICE, the complete runtime controllers and their call sites, and the Editor checks. README/VR_SLICE contain historical descriptions (including paused reload and obsolete encouragement wording); current source and CREATURE_BEHAVIOR are authoritative for implemented controls and saves.

- QuestSlice constructs the world, owns the season, dispatches input, steps villagers, arbitrates curiosity before water work, and saves every 15 seconds. Save state is version 1 with optional backward-compatible fields. It resumes unpaused. Active plans, object novelty and cooldowns generally are not saved.
- CreatureCuriosity executes bounded approach/inspect/lift/play/social/construction/place plans, exclusively owns a held item, and cleans up on reset/disable/timeout. Its scoring currently runs only at rest, but only ranks curiosity affordances. Water is the fallback controller, not part of the same comparison.
- CreatureRoutine executes the existing five-phase pickup/drink/carry/deliver animation/movement loop. Its ownsWater flag and ReturnWater are cleanup boundaries. SeekingWater includes approach movement, so an external owner must identify that stage too.
- Feedback already has A/B, desktop 1/2, aim checks, press edges, simultaneous-input rejection, a receipt debounce, carry/pause gates, a 12-second completion window, one reinforcement per event and immediate affect/haptics. Keep those controls and attribution entry points. Completed curiosity and water events need typed context receipts rather than a second feedback system.
- VillagerRoutine, DroughtSignals, VillagerSocial, VillagerExploration and VillagerBlockPlay already provide independent work, distress, social memory, discovery and reservations. Leisure currently runs before work every frame and can delay shortage requests; urgency must govern that arbitration without deleting leisure.
- CarryItem.held, ConstructionBlock.VillagerOwner and DiscoveryObject.Owner are existing resource reservations. Keep them. A coordinator must not duplicate held transforms or animation controllers.
- ConstructionSite uses one private physics scene per eight-piece tray, saved piece poses/support graphs, safe held snapshots, and an arch recipe. Add bounded learned recipes rather than arbitrary procedural architecture. There are currently three trays; their pieces are not navigation geometry.
- IslandNavigator uses native NavMeshAgent paths in original game units, then projects actors onto the original terrain. Runtime inspection confirmed two NavMeshSurfaces, four agents, zero links and zero dynamic obstacles. Buildings/trunks are baked modifier volumes. AI Navigation 2.0.16 is installed. A walkable bridge requires native routing geometry AND deck-height projection, plus route invalidation/removal safety.
- CreatureAffect and HumanoidMotion/Hands already provide icons, gaze, gestures, reach/carry and reactions. Reuse them; optional explanations belong behind Help/details.
- Existing Editor checks drive controllers synchronously with fixed dt, native physics with tolerances, simulated Touch input, and JSON round trips. They are not headset/performance proof. Preserve the user's save around QA and unrelated local XR settings.

## Missing capabilities and risks

No common water/play utility comparison, contextual reinforcement table, exclusive creature action receipt/coordinator, saved simulation clock, temporary outcome guidance, energy/miracles, injury condition, bounded journal or learned building vocabulary exists yet. Several cooldowns use Time.time and expire while explicit gameplay is paused. Actions are transient on reload, and copied scene searches must stay out of per-frame ranking.

Risks: double ownership between controllers; rewarding a miracle as creature work; category/context learning drifting apart; leisure starving village work; stale targets after reload; native path corner heights flattening bridges into water; bridge removal stranding an actor; incorrectly claiming generic visual understanding or deterministic PhysX; breaking old direct-controller Editor checks. Existing feedback tests call the low-level curiosity API, so compatibility adapters are necessary.

## Integration plan and file-level changes

1. `HybridState.cs`: small serializable clock/guidance/energy/injury/context-learning data with bounded validation and old-save defaults. `WorldEventJournal.cs`: fixed-capacity structured receipts. `CreatureDecisionModel.cs`: plain candidate/context utility and deterministic seeded tie-breaking, without animation or movement. `CreatureHybrid.cs`: one orchestration component combining cached perception, guidance, learning and exclusive action coordination; delegates execution to existing controllers. This consolidates the requested logical boundaries instead of adding seven competing MonoBehaviours.
2. `SliceState.cs`: append validated hybrid state and simulation time. `QuestSlice.cs`: initialize cached targets, use one coordinator for the creature, retain existing input protections, update urgency-aware village scheduling, expose only optional explanations and contextual miracle tools, capture/reload safely. `QuestControls.cs`: preserve bindings; use existing interaction affordances instead of new controller buttons.
3. `CreatureCuriosity.cs`: allow externally selected starts, optional automatic-selection suppression, and typed completion/feedback callbacks. Preserve direct execution for regression checks. `CreatureRoutine.cs`: expose resource feasibility and completion/failure boundaries; keep all five phases. `CreatureAffordance.cs`: stable target IDs and simulation-aware cooldown access. `CreatureAffect.cs`: reuse feedback/intent reactions.
4. `DivineIntervention.cs`: bounded rain/healing effects and contextual world tools, energy checks before spending, paused/suspend-safe durations, no creature completion receipts. `VillagerSocial.cs`: minimal saved injury/assistance outcomes. `VillagerRoutine.cs`, `VillagerExploration.cs`, `DroughtSignals.cs`: maintain independent useful work, distress and social responses while urgency excludes leisure from critical shortages.
5. `ConstructionPatterns.cs` and `CreatureConstructionLearning.cs`: bounded arch, bench-like span and tower templates, observation of authored real-world examples and saved preferences. Extend `ConstructionSite.cs`/`ConstructionBlock.cs` to plan supported placements by recipe while retaining eight-piece saves. Extend `VillageSettlement.cs` with bench observation anchors. Extend `IslandDiscoveries.cs`/`DiscoveryPoint.cs` to persist chosen recipes and integrate construction discoveries.
6. `CreatureBridge.cs`: find a real narrow water gap with dry reachable banks and a measurable land-route detour; build a physical brick span. `IslandNavigation.cs`/`IslandNavigator.cs`: register/remove completed bridge routing geometry, project feet onto deck/ramps, and recover safely after dismantling. Extend `VillagerExploration.cs` for an independent native-path crossing/acknowledgment. Do not create an invisible permanent bridge or a teleport disguised as crossing.
7. `Editor/HybridChecks.cs`, `Editor/BuildingLearningChecks.cs`: fixed-seed utility/learning, action ownership/interruption, guidance expiration/rejection, pause/reload, energy costs/no duplicate effects, autonomous village progress, observation/recipe differences, physical bridge completion and native crossing/removal. Adapt existing test tray selection only where multiple site types require it. Run existing feedback, controls, curiosity, construction, social, discovery, drought, terrain and navigation checks as relevant.
8. Update README, CREATURE_BEHAVIOR and this audit with actual verified behavior, limitations and hardware gaps. Keep normal play nonverbal and the wrist closed by default. Do not rebuild APK or claim Quest comfort/performance without a device run.

## Validation gates

Each code increment must compile, pass its focused Editor checks and relevant regressions, then commit and push on the feature branch. Confirm live frames advance. Validate a full saved season and preserve the pre-test user save. Physics checks use tolerances; logical utility checks use fixed seeds. Only claim a useful bridge after comparing native route lengths and observing a villager actually follow the crossing above the water. Hardware haptics, standalone performance and comfort remain explicit device checks. A reviewable branch targets main; no unrelated XR settings are included.
